# Крупные задачи по системам

Список для планирования. В первой части системы из ADR передачи ставок. Во второй — системы MVP открытия депозитов, без которых не собрать последовательность на дорожной карте. Горизонт года указан отдельно: это целевое состояние, не объём MVP.

## АБС

Команда АБС.

1. Публиковать базовый каталог ставок в сервис открытия депозитов отдельным составом: продукт, срок, границы суммы, базовая ставка, время. Персональные ставки и данные кредитного раздела в это сообщение не входят. Депозитный и кредитный бэк-офис остаются в разных разделах.
2. Java-адаптер читает заявки из Kafka и вызывает процедуры Oracle ограниченным потоком. Статусы открытия возвращаются в сервис.
3. На MVP депозит открывается после подтверждения депозитного бэк-офиса.
4. Горизонт года. Типовой депозит открывается без менеджера бэк-офиса. В отделении достаточно фронт-офиса.

## Сервис открытия депозитов

Команда интернет-банка.

1. Принять каталог из АБС и хранить витрину в своей MS SQL.
2. Отдать кол-центру банка API публичного каталога со временем среза. Тот же каталог уже читают сайт и интернет-банк.
3. Собирать файл каталога и выкладывать его на SFTP одним публикатором. Сбой выкладки не трогает заявки.
4. Принять заявки сайта и интернет-банка, проверить СМС-код и отправить уведомления через действующий шлюз.
5. Горизонт года. Отдавать интернет-банку статус автооткрытия из той же витрины, без релиза каналов.

## Система кол-центра банка

Подрядчик кол-центра и Java-специалисты команды АБС.

1. Карточка текущих ставок для оператора: базовая сетка и время каталога. Чтение идёт в сервис, не в АБС.
2. Хранить последний успешный каталог в PostgreSQL и показывать его, если сервис не ответил.
3. Принять лид заявки с сайта. Особые условия по заявке остаются прежним сценарием через АБС.

## SFTP

IT банка.

1. Каталог для партнёра, вход по ключу, доступ на чтение только этого каталога.
2. Файл заменяется целиком. Обрезанный каталог партнёр не забирает.

## Партнёрский кол-центр

Внешняя компания. Своя система.

1. Забирать файл со SFTP по расписанию. API банка не вызывать.
2. Показать оператору ставки и время файла. Поля клиента, персональную ставку и кредитный риск отбросить, если они попали в файл по ошибке.
3. Консультировать по базовой ставке как по предложению. Особые условия не согласовывать.

## Системы MVP вне этого ADR

Они нужны дорожной карте, потому что витрина и кампания стоят на них.

### Сайт

Команда сайта.

1. Читать каталог депозитов через backend сайта.
2. Принимать заявку: телефон и Ф. И. О. Следующий шаг для клиента — звонок и визит в отделение.
3. Горизонт года. Заявка на кредит с сайта и решение за день, если данных достаточно.

### Интернет-банк

Команда интернет-банка. Ядро монолита подрядчик не меняет.

1. Показать каталог и персональную ставку в веб-приложении.
2. Принять заявку со счётом и суммой, подтвердить её СМС-кодом.
3. Горизонт года. Открытие депозита без бэк-офиса. Заявка на кредит с решением за день.

### Kafka и СМС-шлюз

IT банка.

1. Три темы: заявки, ставки, статусы. В монолит .NET Framework 4.5 очередь не встраивается.
2. Тексты СМС-кода и уведомлений в действующем шлюзе. Модуль СМС в ядре подрядчик не меняет.
3. Горизонт года. Сопровождение очереди и файла. Резервный ЦОД интернет-банка по-прежнему переключается вручную.
